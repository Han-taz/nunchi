# 메모리 모델 v1.4: 주제별 속성 어휘표

상태: 구현 중(U41). v1.3의 키 `(store, subject, attribute)`와 모든 전이 규칙은 그대로다. 바뀌는 것은 "같은 주제인가"를 누가 어떻게 정하느냐 하나뿐이다.

## 1. 문제

v1.3 라이브 시뮬레이션에서 추출기가 속성을 자유 문장으로 지었고, 같은 주제인지는 haiku 판정자가 값마다 다르게 판정했다.

| 관찰 | 결과 |
|---|---|
| `--color-border 대비`(1.4:1) 행이 `텍스트 삼차색 대비 2.46:1` 행에게 교체됐다 | 다른 주제인데 같은 속성에 들어가 앞의 결정이 사라졌다 |
| "반영 방식" 스와치 결정을 말만 바꿔 다시 말한 글이 재확인이 아니라 교체가 됐다 | 같은 결정이 superseded 이력으로 쌓였다 |
| 한 결정이 `cloudflare beacon`과 `v1.0 포함 여부` 두 속성으로 갈라졌다 | 키가 둘이라 서로 충돌하지 않는다 |
| 속성 이름이 문장 전체다 (`프론트 ?next= 처리는 pr #21과 …`) | 키가 제목이라 재사용되지 않는다 |

원인은 하나다. 같은 주제인지의 기준이 속성 이름과 값의 문장이었고, 그 문장은 매번 다시 지어졌다.

## 2. 자료 모양

`attribute_vocab(tenant_id, store_id, subject_id, key, label, question)`, 기본키 `(store_id, subject_id, key)`. `memory.attribute`는 이 `key`를 그대로 쓴다. 유일 인덱스와 전이 규칙은 바뀌지 않는다.

- `key`는 40자 이하의 짧은 슬러그다. `app_sec.norm_text`를 거친 모양이어야 한다(CHECK).
- `label`은 사람이 읽는 이름, `question`은 "이 속성이 무엇에 답하는가"를 적은 한 줄이다(예: `border 색의 대비 비율`, `프론트 ?next= 처리를 누가 구현하는가`).
- 읽기는 store reader, 쓰기는 `app_sec.register_attribute`(contributor)뿐이다. 이미 있는 키는 덮어쓰지 않는다.

## 3. 판정 규칙

1. 추출기는 주제의 어휘표(key, label, question)를 받아 그중 하나를 고르거나, 새 항목(key, label, question)을 제안한다.
2. 서버는 제안된 key가 어휘표에 있으면 그 항목을 쓴다. 없으면 기존 항목들과 질문끼리 비교한다("두 질문이 같은 것을 묻는가"). 같은 것을 묻는 항목이 있으면 그 key로 옮기고, 없을 때만 새 항목을 만든다. 값은 비교하지 않는다.
3. 같은 key는 구성상 같은 주제다. 같은 key에 다른 값이 오면 v1.3의 challenge와 supersede 규칙이 그대로 일을 한다. 값끼리의 "말만 바꾼 같은 결정" 판정(`canonical_value`)은 남지만 한 질문 안에서만 일어난다.
4. 판정자 오류나 판정자 없음은 항상 "다른 질문"이다. 새 항목이 생길 뿐 기존 결정은 교체되지 않는다.

삭제된 것: 값으로 주제를 판정하던 `keep_topic`과 `reuse_attribute`, 후보의 속성을 그대로 베끼게 하던 추출 규칙.
